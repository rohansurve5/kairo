# Kairo decisions

## Locked decisions (from the maintainer, prompt 2, 2 Nov 2026)

1. **CV PDF** is built by a Python script inside the skill (no Chrome): `skill/kairo/scripts/build_cv_pdf.py`.
2. **Truth checker** is a Python script inside the skill: every number, company, title and date in the CV / cover letter must exist in the user's "my facts"; plus banned claims, word limits and the share of bullets with numbers: `skill/kairo/scripts/truth_check.py`.
3. **Privacy.** The user's CV, my-facts, salary, cover letter and form answers stay in the user's own Claude project. The server stores only: jobs (public JD data), fit score, verdict, red flags, visa flag, status history with dates. Plus consent, regenerate-link and delete-my-data.
4. **No third-party content.** No paid-coach material, no purchased directory lists, no copied design notes. The Geist font is OFL and allowed (bundled in the skill with its licence).
5. **German CV:** photo and date of birth optional, default OFF (rules say "check current advice").
6–8. **Server decisions** (database, duplicate check, hosting) live in the private `kairo-cloud` repository.
9. **Name:** Kairo. **Licence:** MIT.

Also fixed: the optional dashboard server uses zero AI (all AI work happens in the user's own Claude); no auto-apply, ever; never invent facts.

| A10 | Red flags go to the server as code + public text with no user numbers                                                                                                                                                                            | e.g. "Posted salary is below your minimum", never the minimum.                                                                                   |
| A11 | Status list: checked, ready, applied, replied, interview, offer, rejected, skipped, withdrawn, on_hold                                                                                                                                           | Covers "got reply" and the old system's statuses, in plain words.                                                                                |

| A13 | Visa thresholds are never hard-coded in the skill; Claude checks the official page and gives the date                                                                                                                                            | They change every year.                                                                                                                          |
| A14 | Delete / regenerate / consent are dashboard pages, not MCP tools                                                                                                                                                                                 | Claude can never delete data by mistake.                                                                                                         |

| A16 | Never guess money: a missing salary ask or floor is asked, never filled in (`form_answers.py` prints ASK THE USER) | User request, prompt 3. |
| A17 | Every reply ends with one clear next step | Non-technical users. |
| A18 | Dashboard link only in `skill/kairo/config.json` (`launched: true` since launch, 4 Nov 2026); invites only after setup, after the 3rd job and on "show my jobs", never once connected | One place to change at launch. |
| A19 | Model names only in `references/model-tips.md`; light tasks → faster model, pack → strongest model; no tips for free-plan users | Saves the user's usage. |
| A20 | Forms that forbid AI: CV only; the user writes the letter and answers | Respect employers' rules. |

## Decisions from prompt 4 (3 Nov 2026)

| #   | Decision | Why |
| --- | -------- | --- |
| L1  | Login for the dashboard and the connector: WorkOS AuthKit, email + 6-digit code only (no passwords); Google later. The same account is used on the website and in the Claude connector. | Maintainer decision. |
| L2  | The connector URL is plain (`https://kairo.rohansurve.in/mcp`, in `config.json` as `connector_url`); no secret links. | Nothing secret in URLs or logs. |
| L5  | Contract roles, relocation and shift/night work are asked at setup. Not open → Skip. Open → note only. Not in my-facts → note and ask, never Skip. | Maintainer decision. |
| A21 | Never write a work preference (relocation, contract, shifts, travel, notice/start, salary) in a letter or answer unless my-facts says it; `truth_check.py` fails it, `form_answers.py` prints ASK THE USER. | Never invent facts. |
| A22 | Model tips are about the **next** step: the "strongest model" tip goes in the job-check reply before "make the pack". | The old rule tied the tip to the pack reply itself, so it could only come after the pack. |
| A23 | New red flag code `shift_work` (contract v1.2). | Night / rotational / US-UK shift roles. |
